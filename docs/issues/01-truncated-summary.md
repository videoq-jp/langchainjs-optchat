# [P2] LangChainコンプレッサーが打ち切られた応答を正常な要約として保存する

## 問題

`src/langchain/index.ts`の`createLangChainCompressor()`は、文字列の有無・サイズ・ツール呼び出しだけで応答を採用し、終了理由を確認しない。元の`src/core/compactor.ts`は`stopReason === 'length'`の応答を採用せず再試行する。

## 再現

モデルの`invoke()`から次のAIMessageを返す。

```ts
new AIMessage({
  content: 'Incomplete fact: the selected account is',
  response_metadata: { finish_reason: 'length' },
});
```

長さが512バイトを超える入力をコンプレッサーへ渡すと、上記の未完文が1回の呼び出しで正常な要約として返ることを確認した。

## 影響

途中で切れた決定事項や数値が完成済みツリーに保存され、以後の増分処理でも再利用される。

## 完了条件

- [ ] サポートするモデルの標準的な終了理由を扱い、トークン上限等で打ち切られた応答を完成した要約として保存しない。
- [ ] 元実装に合わせて試行回数を制限し、全試行が不適切な場合のRefused／フォールバック動作を保持する。
- [ ] 正常終了、打ち切り後の成功、連続打ち切り、空応答、ツール呼び出し、キャンセルの回帰テストを追加する。
- [ ] 採用されなかった断片が完成済みノードに保存されないことを検証する。

## 対象と前提

`langchain-optchat@0.3.0`のローカル移植版を対象とするレビュー指摘。元リポジトリの既存Pi実装に対する不具合報告ではない。レビュー時のベースコミットは`c1c4cac95bf971577638e4dbd73797363bc5e815`で、移植コードは未コミット。
